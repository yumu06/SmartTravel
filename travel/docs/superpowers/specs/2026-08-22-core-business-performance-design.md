# 核心业务性能压测与优化设计

日期：2026-08-22

## 目标

为鉴权、用户信息、文章详情和推荐四条核心读链路建立可重复的本地性能基线，再依据实际瓶颈实施 Redis 缓存、SQL 与服务配置优化。所有测试数据写入独立的 `travel_benchmark` 数据库，不污染当前 `travel_database`。

## 范围

第一轮包含：

- `GET /travel/authorization`
- `GET /travel/user/info`
- `GET /travel/post/show/:id`
- `GET /travel/post/recommand?limit=20`

点赞、收藏、评论等写链路在读链路稳定后单独压测，避免读写竞争影响第一轮结论。微信登录和腾讯位置服务不参与压测，防止消耗第三方配额。

## 隔离环境

- 保留当前 `travel_database` 和 1016 端口服务。
- 新建 `travel_benchmark` 数据库。
- 压测服务使用 1017 端口、独立临时 JWT 密钥和同一个本地 Redis 实例。
- Redis 压测 Key 使用现有 `travel:` 规范，并在压测前后按明确的压测 SID/Key 清理，不执行模糊批量删除。
- AppSecret、数据库密码和 JWT 密钥只通过环境变量注入，不写入压测报告。

## 测试数据

数据生成器必须幂等，并使用可识别的固定范围：

- 用户：1,000
- 文章：10,000
- 评论：50,000
- 点赞关系：100,000
- 收藏关系：30,000
- 足迹：10,000

文章发布时间、作者、热度和内容长度采用确定性分布，以便每次重建得到等价数据。为避免 AutoMigrate 与批量数据互相干扰，生成顺序为建库、迁移、批量插入、校验行数。

## 鉴权方案

压测工具不调用微信 `jscode2session`。设置一个固定压测用户，使用与 1017 服务相同的临时 JWT 密钥签发 Access/Refresh Token，并在 Redis 中创建对应 Refresh Session。Access Token 通过环境变量传给压测工具，不写入命令历史、源码或报告。

压测工具支持 `Authorization: Bearer`，并输出成功 QPS、错误率、P50、P95、P99、最大延迟、HTTP 状态分类和网络错误样例。

## 压测流程

每个接口依次执行：

1. 单请求正确性检查。
2. 并发 10 冒烟。
3. 并发 50 基线。
4. 并发 100、200 阶梯升压。
5. 仅在错误率低于 1% 时继续提高并发。

文章详情使用多个文章 ID 轮询，避免只测一个热点对象。每轮压测前确认 1017、MySQL 和 Redis 可用，压测后确认服务仍能响应。

基线目标不是预设真实性能，而是统一验收阈值：

- HTTP/网络错误率低于 1%。
- P95 低于 200ms。
- 不调用第三方接口。
- 服务压测后仍可用。

## 观测内容

- HTTP：成功 QPS、P50/P95/P99、错误分类。
- Go：CPU、堆、goroutine、mutex/block profile（发现异常后启用 pprof）。
- MySQL：慢查询、连接池等待、正在使用连接数、关键 SQL 的 EXPLAIN。
- Redis：命中率、错误数和单次访问延迟。
- 服务日志：压测默认关闭逐请求访问日志，只保留错误和慢查询，避免终端 I/O 污染结果。

## 优化顺序

只针对基线证据实施优化：

1. 服务运行模式与访问日志开销。
2. 鉴权链路用户缓存，减少每请求 MySQL 用户查询。
3. 文章详情 Cache Aside、随机 TTL、空值缓存与 singleflight。
4. 推荐查询的候选集与短 TTL 结果缓存。
5. SQL 索引、查询次数和连接池参数。

每项优化独立完成并复测，不把多项改动合并到同一个 Before/After 结果中。

## 错误处理与安全

- 数据生成失败立即停止，不对现有数据库回退执行。
- Redis 不可用时压测服务启动失败，避免把降级路径误当成缓存基线。
- Token 无效、数据缺失或接口返回非 2xx 时计为失败，不吞掉错误。
- 不在报告中记录 AppSecret、数据库密码、JWT、Refresh Token 或用户 SessionKey。
- 不删除 `travel_database`、现有 Redis 会话或用户真实数据。

## 交付物

- 幂等的基准数据生成命令。
- 支持 Bearer Token 和多 URL 的 Go 压测工具。
- 四个核心读接口的基线报告。
- 每项实际优化的 Before/After 对比。
- 完整测试、`go vet` 与构建验证结果。
